# App Frontend — SPA

Single Page Application (React / Vue / Angular), built from Git and served via nginx.

## What It Demonstrates

- **`type: git`** — build from Git repository
- **Static `docker-stack.yml`** — no Jinja2, alternative approach to templates
- **Build args** — `NODE_ENV`, `VITE_API_URL`, `VITE_APP_TITLE` passed during `docker build`
- **`TAG_*` variable** — `${TAG_FRONTEND}` is automatically generated by CLI during build
- **Traefik labels** — routing to root domain
- **Rolling update** — `order: start-first` for zero-downtime deploy
- **No secrets** — SPA embeds configuration at build time via build args

## Files

```
app-frontend/
├── services.yaml       — git service with build args
├── variables.yaml      — build variables (NODE_ENV, VITE_API_URL)
├── settings.yaml       — fast startup (15 sec), long build (600 sec)
├── externals.yaml      — empty (no secrets needed)
├── docker-stack.yml    — Docker Compose for Swarm
└── README.md
```

## SPA and Environment Variables

Unlike backend services, SPA cannot read environment variables at runtime. All values are embedded at build time via build args:

```yaml
# variables.yaml
build:
  NODE_ENV: production
  VITE_API_URL: https://api.example.localhost/api
```

```dockerfile
# Dockerfile (in frontend repository)
ARG NODE_ENV
ARG VITE_API_URL
RUN npm run build
```

For different environments (dev / prod), use different profiles with different `variables.yaml`.

## Rolling Update

Configured with `start-first` update order — new replica starts before old one stops:

```yaml
deploy:
  replicas: 2
  update_config:
    parallelism: 1
    delay: 5s
    order: start-first
```
